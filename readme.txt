【概要】
このアプリケーションは、DMM GAMES 艦隊これくしょん ～艦これ～ の
Webページを全画面表示するだけのElectronベースのブラウザアプリです。
ホントそれだけで他には何にもしてません。

タブレットPCやモバイルモニタなどでタッチパネル操作するのに便利です。
ネットサーフィン中のブラウザの操作に巻き込まれて落ちないので安心。

【動作環境】
- Windows 10/11 (64bit)

【使い方】
普通にインストーラを使ってインストールして下さい。

1. アプリを起動すると、DMMのログイン画面が表示されるのでログインしてください
2. 自動的に艦これが全画面表示されます
3. F11 または Ctrl+Space で全画面/ウィンドウモードを切り替えられます
4. ESCキーを5秒以内に2回押すとアプリが終了します
   （1回目のESC後、Spaceキーでキャンセル可能）
5. 文字入力（艦隊名など）は物理キーボードで行います
   （OSのタッチキーボードは抑止されたままなので表示されません）

  【修正・変更の要旨】
  - 文字入力時のグレーアウト修正: フォーカスを奪わない方式に変更（抑止はinputmode属性のみ、
    物理キーボード入力可）。フォーカスspoof追加（当アプリではウィンドウを常時「フォーカス
    あり」とみなし、フォーカス喪失を艦これ本体に伝えない）
  - タッチ由来ホバー（当たり判定）の残滓の修正（v5最終仕様）: タッチ運用中の純ホバー
    （ボタン非押下）は遮断。実マウス→タッチ切り替え時とタップ終了（動かずに離された時）に
    限りホバー状態の解除を要求し、CDP（webContents.debugger attach('1.3') +
    Input.dispatchMouseEvent）で「本物の入力」を「何もない所」（ゲーム領域内の左上隅）に発射。
    ボタン押下中（press→move→release＝ドラッグ列）は什么都许容（操作そのものだから）
  - 開発画面ドラッグ＆ドロップへの干渉修正: 上記v5の一部。ドラッグの「離された瞬間」に
    当方の解除が割り込み、ドロップ先が列表本体（＝レシピ消去）になっていた現象を解消
  - Electronを28.3.3→45.3.2へアップデート（ユーザー指示）
  - 構造: 艦これ本体はクロスオリジンiframe（osapi.dmm.com/gadgets…）＋入れ子フレームで
    動く（実機プローブで確認）。注入スクリプト（フォーカスspoof／タッチホバー抑止／
    入力ポリシー／マウスガード）はファイル化し、ルート以外は全フレームに実行する
    （DOMイベントは文書を跨がないため、実bodyのいる文書に注入しなければイベントが見えない）
  - 出力をUTF-8に統一（旧Shift_JIS変換を廃止。ターミナル側もUTF-8で表示のこと）。
    確認用ログは最小化済み（動作ログはCDP実行時＋エラー時のみ）
  【確認した事実・はまった点（教訓）】
  - JS合成イベント（dispatchEvent）はゲームに反応されない。聞かれるのはtrusted入力のみ
  - debugger.attach()の引数はプロトコルバージョン。識別子を渡すと失敗する
  - sandboxワールドではプレロードと注入スクリプトのグローバルは共有できない。
    世界の壁を跨げる確かな経路はコンソール中継
  - テストハーネスは同一世界で走るため世界の壁を写せない。実機ログが唯一の証明
  - Electron v28でframesInSubtree（v30+で追加）を使っているとスキャンが黙って空振りする
  - グレーアウト瞬间のDOMフォーカス系イベントは事後症状（判定はプレーヤー内部）。
    上流修正（Ruffle PR #23204）が本筋
  - 開発レシピのドラッグはゲーム唯一の「本物のドラッグ＆ドロップ」画面。他画面の
    「入れ替え」はクリック→クリック操作なので干渉面が違った
  検証テスト4本（touchhover/focusspoof/inputpolicy/mouseguard）全通過
- 2026-11-17: v1.0.5（追記・インストーラ差し替え）ゲーム領域下端の境界に白ラインが残る問題への対応。
  ゲームページ本体（gadget文書）の背景が白で、キャンバススケーリングのサブピクセル誤差で
  下端1pxほど白が覗いていた（黒地はgame_frameより下なので内側の白は塞げない）。
  全フレームへの注入スクリプトにdark-bg.jsを追加（文書側の背景を黒に。トップフレームの
  ブックマークレットと同じ処理のフレーム版・冪等）。併せてウィンドウ自体の背景色も黒に
  （未描画領域・OS角丸マスクの欠け部分の白対策。ウィンドウ内の白はこれで全て黒くなる）
